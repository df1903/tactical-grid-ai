\chapter{Línea de Comandos (CLI)}
\label{man:cli}

\section{Uso Básico}
\label{sec:cli-basico}

\begin{minted}{bash}
uv run python -m tactical_grid <scenario.json> [opciones]
\end{minted}

Las opciones sobrescriben la sección \code{prueba} del JSON.

\section{Listas Comma-Separated (Sweep Combinatorio)}
\label{sec:cli-sweep}

Las opciones \code{--algorithm}, \code{--heuristic}, \code{--k}, \code{--depth}, \code{--order}
aceptan listas separadas por comas y ejecutan \textbf{todas las combinaciones} (producto cartesiano)
que apliquen.

\begin{minted}{bash}
# Beam k=1,2,4,8 con H1
uv run python -m tactical_grid scenarios/caso_05_beam_k.json \
    --algorithm BEAM --heuristic H1 --k 1,2,4,8 --verify --csv beam.csv

# Minimax frente a alfa-beta, profundidades 1-4, órdenes predeterminado e invertido
uv run python -m tactical_grid scenarios/caso_07_decision_adversarial.json \
    --algorithm MINIMAX,ALPHA_BETA --depth 1,2,3,4 --order default,reversed --verify

# Sweep completo: todos los algoritmos, heurísticas, k, depths, órdenes
uv run python -m tactical_grid scenarios/apendice_a.json \
    --algorithm BFS,DFS,UCS,A_STAR,BEAM \
    --heuristic H1,H2 --k 1,2,4,8 \
    --depth 3,4,5 --order default,reversed \
    --verify --csv results.csv --json results.json
\end{minted}

\section{Variante dinámica}
\label{sec:variante-dinamica}

La variante se activa con \code{--variant dinamica} o mediante \code{"variante": "dinamica"}
en la sección \code{juego} del JSON. Mantiene el objetivo de llevar el recurso a la base,
pero aplica dos reglas adicionales:
\begin{itemize}
\item El costo del terreno se convierte en turnos de recuperación propios; una unidad en
  recuperación no puede actuar hasta quedar libre.
\item Un placaje puede robar el recurso y el portador conserva inmunidad durante los turnos
  indicados por \code{juego.inmunidad\_robo}.
\end{itemize}
Los algoritmos disponibles para esta variante son Minimax dinámico y Alfa-beta dinámico.

El sweep ejecuta el producto cartesiano de todas las combinaciones válidas (heurística solo para
A*/Beam, k solo para Beam, depth/order solo para Minimax/$\alpha$-$\beta$).

\section{Ejemplos de Uso Común}
\label{sec:cli-ejemplos}

\subsection{Búsqueda simple con verificación}
\begin{minted}{bash}
uv run python -m tactical_grid scenarios/apendice_a.json \
    --algorithm A_STAR --heuristic H2 --verify
\end{minted}

\subsection{Adversarial con verificación (check 6)}
\begin{minted}{bash}
uv run python -m tactical_grid scenarios/caso_07_decision_adversarial.json \
    --algorithm ALPHA_BETA --depth 4 --verify
\end{minted}

\subsection{Partida completa desde la terminal}
\begin{minted}{bash}
# IA contra IA
uv run python -m tactical_grid scenarios/caso_07_decision_adversarial.json \
    --mode partida --play auto --algorithm ALPHA_BETA --depth 3

# Persona contra IA
uv run python -m tactical_grid scenarios/caso_07_decision_adversarial.json \
    --mode partida --play humano --side A --depth 3

# Variante dinámica
uv run python -m tactical_grid scenarios/caso_11_dinamico.json \
    --mode partida --play humano --variant dinamica --depth 3
\end{minted}

Sin \code{--play}, \code{--mode partida} solo describe el estado cargado. Con
\code{--play humano}, las acciones legales aparecen numeradas y se responde con un número;
\code{q} abandona la partida. Con \code{--play auto}, el reporte incluye el desarrollo completo
de la partida.

\subsection{Sweep de rendimiento (caso 10.5 del informe)}
\begin{minted}{bash}
uv run python -m tactical_grid scenarios/prueba_15x15.json \
    --algorithm ALPHA_BETA --depth 5,6,7 --csv docs/results/rendimiento_15x15.csv
uv run python -m tactical_grid scenarios/prueba_15x15.json \
    --algorithm MINIMAX --depth 4,5,6 --csv docs/results/rendimiento_15x15_minimax.csv
\end{minted}
